# AI 监管层需求变更点确认记录（2026-08-14）

> 依据：`ai接入优化方案详细.md` §9.3。以下 7 个变更点已逐项获得用户确认（用户自定义回复），是 AI 监管层 Phase 0–6B 的实施约束。

## 确认结论

| # | 变更点 | 用户确认结论 | 实施含义 |
|---|---|---|---|
| ① | 无 AI 回退能力 | **自动降级但保留**：AI 大部分时候只是加强、并非不可或缺；无 AI 时系统正常运行，默认部署就是无 AI；有 AI 后系统自动判定可用性并自动触发更高级检测，恢复后自动还原 | AI off 时零行为差异；AI on 时自动升级检测；删除/禁用 AI 不影响 R01–R22 任何既有能力；`enabled` 默认 false |
| ② | 部署与数据驻留 | **全部接入第三方 API**：支持 OpenAI Chat Completions、OpenAI Responses、Anthropic、Gemini 等原生格式 + OpenAI 兼容格式；模型/URL/Key 完全用户自定义（类似 Cherry Studio）；系统负责请求构造、响应解析、agent 设计与接入层级 | Provider 适配层必须支持多供应商原生格式与 OpenAI 兼容端点；配置为 URL+Key+Model 全自定义；无缓存问题（每次请求最新）；禁止自托管模型假设 |
| ③ | 冲突正文外发 | **允许部分发送正文或特殊情况**：大部分时候只需要文件信息即可，不需要 AI 处理具体冲突；特殊情况由系统自己判断是否发送受限正文 | 默认只发元数据聚合；系统自判（preview_eligible + secret scan + 字节/类型上限）的特殊情况可发送受限正文片段；原件永不覆盖 |
| ④ | 采纳模式 | **设计好 AI 参与程度，系统自动运行**：不是所有都需要管理员确认；严格按文档规范 AI 能力边界，保证 AI 不会毁灭运行 | 低风险可逆场景（巡检摘要、告警说明、列表排序、轮询优先级）允许 `auto_low_risk` 自动采纳；灾难、身份、接管、冲突发布建议始终人工确认；任何 AI 建议必须经 validator + 硬门槛 |
| ⑤ | 审计保留期 | **保留必要摘要（黑盒子）**：能还原 AI 的所有决策与实施的功能即可，不用太复杂 | 存脱敏 observation（或 digest）+ 建议 + 采纳/拒绝结果 + validator 结果；不存正文/密钥；可重放"当时看到什么、建议了什么、最终怎样" |
| ⑥ | 费用预算 | **设计好调用频率/上下文/提示词**：不能太低也不能过于频繁；保证必要检测都有；可被动触发（如故障时触发 AI 作保障）；不在意 API 消耗预算 | 低频巡检（默认 5–10 分钟集群巡检）+ 事件/故障被动触发 + 同 dedup_key 去重；不设硬费用熔断，但技术故障熔断与频率上限保留 |
| ⑦ | 模型升级权 | **模型完全用户自定义**（URL/Key/模型名，类似 Cherry Studio）；系统只做好请求、解析、提示词、上下文、agent/提示词框架 | 不做模型版本管理/pinned snapshot 升级流程；模型配置随用户配置变更即时生效；schema/prompt 版本仍固定并由 validator 校验 |

## 实施边界（不变）

- AI 不在任何请求关键路径；后台 worker 与业务请求解耦
- 所有原 deterministic function 保留并成为 fallback
- AI 建议不是 Store truth，不被 Agent 信任；不扩展 Agent 命令面
- R03/R04/R06–R08/R10–R15/R17/R22 安全断言与 AI 无关
- 不保存完整敏感 prompt；保存脱敏 observation 或 digest
