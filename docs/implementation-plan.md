# 全量实施计划

更新日期：2026-08-07

本计划不采用“先做看起来能演示的 MVP”作为完成标准。实施按依赖顺序小步提交，但最终必须通过 `docs/requirements-traceability.md` 的逐条验收。

## 0. 基线、仓库与证据

- 建立 stcontrol Git 仓库并绑定 `https://github.com/inliver233/stcontrol.git`，忽略二进制、前端构建产物、本地配置和运行数据。
- 保存需求追踪矩阵、架构决策和验证记录。
- 为 Go 与 React 建立可重复测试、覆盖率、lint、集成环境和安全测试入口。
- 处理 `Sillytarven-online` 既有联邦登录 WIP 前先确认归属；不得覆盖或回退。

退出条件：工作树归属清楚；基线测试记录可复现；远端已保存首个可构建提交。

## 1. PostgreSQL 事实模型与事务原语

- 用有版本的迁移替代单个 `CREATE TABLE IF NOT EXISTS` 字符串。
- 落地控制世代、节点/凭证/接入令牌、全局用户/多身份、节点账号、活动租约、快照/副本、工作流/步骤、票据、管理员关联、审计和告警。
- 为活动租约获取、票据消费、接入令牌消费、工作流认领、副本发布、控制世代提升实现事务与条件更新。
- 所有跨服务操作使用稳定 operation ID；数据库记录请求摘要而不是密码/token。

退出条件：迁移可从空库运行、重复运行和升级；并发测试证明单用户只能取得一个 writer，票据和令牌只能消费一次，世代只能单调增加。

## 2. 安全票据与持久总控会话

- 明确互斥票据类型：用户登录、节点管理员跳转、灾难接管、Agent 数据传输 capability。
- 强制算法白名单、`typ/iss/aud/sub/user_uuid/node_id/session_id/activity_epoch/ticket_type/iat/nbf/exp/jti/kid/controller_generation`。
- 浏览器只通过 POST body 或一次性短码交换，不把 JWT 放入 URL；响应设置 `Cache-Control: no-store` 和严格 Referrer Policy。
- 总控用户/管理员会话持久化、可撤销、Secure Cookie、CSRF 防护、会话轮换和限流。

退出条件：所有 claim 缺失/错误、类型混淆、重放、错节点、旧世代、日志/Referer 泄露测试通过。

## 3. Agent enrollment 与主动控制通道

- enrollment token 哈希存储、短期、一次性并绑定角色、安装 operation、初始指纹。
- Agent 主动建立 TLS 出站长轮询（或同等 ACK 通道），支持断线重连、命令 ACK、幂等领取、控制世代拒绝和本地持久执行状态。
- Controller 不再依赖访问节点的 loopback `agent_url`；固定命令清单替代任意 HTTP/任意 shell。
- 每任务数据传输 capability 替代把目标永久 PSK交给源 Agent；控制面与数据面使用独立连接和限额。

退出条件：NAT 场景可工作；旧世代/重复命令/过期 capability 被拒绝；Agent/Controller 任一重启后任务可自动对账。

## 4. SillyTavern federation control adapter

- 默认关闭且不改变独立节点行为。
- 安全联邦登录入口建立带活动世代的本地 cookie session。
- 受控模式关闭原生登录/注册/OAuth 首次注册/身份绑定/改密/删号；独立和 draining 模式按确认语义开放或关闭。
- 仅 loopback/Unix socket 的内部控制 API：精确账号扫描/供应、兼容 scrypt 材料、注册策略、模式、用户写门、排空、能力/版本/插件指纹。
- 用户级请求守卫跟踪页面存活、读写在途、拒绝陈旧会话，并保证冻结超时最终释放。

退出条件：原生入口无法绕过；A 活动时 B 写入和陈旧标签页均被拒绝；独立模式仍可按规则运行；现有酒馆独立模式回归测试通过。

## 5. 身份、注册、迁移和管理员闭环

- 账号密码、Discord、LinuxDo 三种身份；最多三种、至少一种、无邮箱。
- 注册 saga 对节点选择、邀请码策略版本、节点账号供应和不确定结果实现幂等查询/重试，不静默换节点。
- 密码只保存控制面验证 hash 与酒馆兼容 scrypt hash/salt；版本化同步全部计算账号，部分失败保持旧版本并重试。
- Agent 扫描真实账号/OAuth/管理员和目录；稳定 OAuth 自动关联，同名密码账号进入控制权证明与合并/区分流程。
- 多个同级总控管理员、逐节点管理员关联和专用短期跳转票据。

退出条件：三种身份、绑定/解绑、管理员恢复、邀请码未知、响应丢失、密码部分失败、老账号冲突全部有集成测试。

## 6. 用户活动租约与节点选择

- 浏览器页面 lease、请求活动、写入在途和 15 分钟离线宽限分开记录并参数化。
- 登录选点事务：已有活动 writer 时只返回原节点；无活动 writer 时只从已同步且兼容的计算副本中授予新 epoch。
- 低频后台页面保活；旧页面恢复展示重新登录且禁止写。
- 用户界面只显示当前节点、推荐、延迟、运营状态和保护状态。

退出条件：多标签页、休眠、网络抖动、并发选点、租约过期、A/B 争抢的自动化测试通过。

## 7. 一致性快照、传输、发布和恢复

- Controller 持久工作流和 Agent 本地任务状态实现完整状态机。
- 写门关闭、排空、同文件系统任务临时快照、不可变 snapshot ID、规范 manifest、zstd/tar 流。
- 解包限制路径、符号链接、文件类型、单文件/总大小/文件数、压缩比和磁盘预留；目标重算 manifest 后原子发布。
- 用户任何阶段回归时双端幂等取消/清理并放行用户；旧成功副本保持不变。
- archive 恢复到用户选择的合格计算节点；账号供应与兼容门禁一起完成后才可登录。

退出条件：用户回归、断网、磁盘满、恶意归档、重复任务、重启、校验失败均不发布半副本、不删除旧副本、写门最终释放。

## 8. 副本、容量、故障和冲突状态机

- 常态一个活动计算副本 + 一个纯存储副本；只留最新成功副本。
- 指标窗口、50% 降权、持续 60% 硬门槛、实际磁盘字节、分配配额、高低水位、滞回和冷却。
- 纯存储故障优先迁移其他存储；无合格目标标记未保护，不强塞计算节点。
- 显式/临时计算热备、节点回归陈旧、稳定观察后清理。
- 真实分叉冻结用户并保留 A/B 原始快照；支持不同路径自动合并、已知类型辅助、不可合并文件选边/双份保留。
- 节点 maintenance/draining/retiring/decommissioned、升级隔离、按用户完整性检查和恢复。

退出条件：计算/存储故障、陈旧副本、分叉、退役、升级失败、静默损坏测试全部通过。

## 9. 独立灾难模式与控制面高可用

- 短失联继续已有合法会话，暂停新登录/选点/调度；多信号确认后进入 independent。
- 仅最后活动节点允许已有账号原生登录；禁止注册和身份修改；双故障由用户确认风险后接管。
- 主控恢复进入 `independent-draining`，停止新原生登录，已有会话自然结束后逐用户对账/同步/纳管。
- 一个活动主控与零到一个被动副控；更高 generation 才能接管，恢复后轮换 Agent 凭证、撤销旧票据并对账。
- PostgreSQL、配置和密钥恢复材料纳入控制面灾备演练。

退出条件：抖动、长期失联、网络分区、双主、副控接管、主控恢复 drain 和密钥轮换全部通过故障注入。

## 10. 控制台、告警和规模化门禁

- 所有用户页和管理员页使用真实 API、权限、加载/错误/空状态、分页/筛选、任务进度、审计和响应式布局。
- 告警按用户影响、保护丢失和持续时间分层；自动重试期间抑制噪声，无法收敛才升级。
- 登录、心跳、调度、队列、备份和 PostgreSQL 目标规模压测；控制与传输互不饥饿。
- Ubuntu、Debian、CentOS 安装/升级/卸载/权限回归；运行手册、恢复演练和发布清单。

退出条件：需求矩阵 R01-R22 全部具有代码位置、测试和运行证据；没有占位实现、假成功按钮或 README 过期声明。

## 首批实现顺序

当前最短关键路径为：

1. 版本化事实模型与事务原语；
2. 严格票据 profile 和无 URL 凭证交换；
3. Agent 主动命令通道与世代；
4. SillyTavern adapter 的租约/写门原型；
5. 不可变快照安全原型。

这五项会先形成独立、可测试提交；之后才扩展身份、故障、控制台和规模化能力。
